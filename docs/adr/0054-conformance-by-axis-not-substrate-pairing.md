# Conformance by axis, not by substrate pairing

Status: Accepted

The mechanism battery is split into two **axis batteries** — a **streaming battery** and a **persistence battery** — instead of the per-pairing cross matrix ADR-0027 established. Each battery exercises exactly one axis against a real backend and fakes the other axis with a **dumb reference** that honours the contract but is never asserted upon:

- The **streaming battery** binds `{AQS, Kafka}` with a **real broker** and **reference persistence** (Orleans memory grain storage + in-memory `ReferenceTableStoreFactory` / `ReferenceClaimCheckStore`). Its fixture surface (`StreamingConformanceFixture`) exposes only the publish seam, the grain probes, and a claim-check existence probe — so a streaming scenario physically cannot assert a durable-store property.
- The **persistence battery** binds `{Azure Table/Blob, Postgres}` with a **real store** and a **dumb deliver-once `MemoryStreams`** reference (delivers once to implicit subscribers, carries the `EventId` intact, never redelivers). Its fixture surface (`PersistenceConformanceFixture`) exposes the send seam, grain probes, and the durable table read/write seams — so a persistence scenario can never assert an ordering, partitioning, trace-propagation, or transport-timing property of the stream.

Substrate-independent scenarios (command validation, span parentage, the dedup-span emission, window-size config read, the in-memory claim-check key contract) are demoted to `Edict.Core.Tests` and run **once**, not per provider. The irreducible interaction — full-stack composition boot and the write-fault ∧ redelivery conjunction — lives in `Edict.Pairing.Tests` as a thin per-pairing smoke, not a battery. This is the four-bucket model: substrate-independent → run once; streaming-axis → streaming battery; persistence-axis → persistence battery; irreducible interaction → pairing smoke.

The architectural thesis is that the Outbox already decouples persistence from streaming — a command commits `{State, Outbox}` in one grain-state write and the drain publishes separately, with no distributed transaction joining them — so the test architecture should mirror that decoupling. A "pairing" (e.g. "Azure") dissolves as a *test* concept into two unrelated axis-providers (`Azure.Streaming` and `Azure.Persistence` are independent packages per ADR-0042); pairing survives only in the bucket-4 smoke and in the benchmark harness. The **reference-fidelity contract** is the design invariant: each battery asserts only its own axis, and the faked axis honours the contract (at-least-once deliver, `EventId` integrity, state reload) but is structurally unable to be asserted upon — the two fixture-base surfaces make the `azure-queue-trace-propagation-gap` green-and-wrong failure mode impossible by construction.

`Edict.Substrate` / ADR-0030 is **untouched** and stays benchmark-only: conformance fixtures host their backends directly (assembly-shared testcontainers + Orleans `TestCluster`), with no conformance → `Edict.Substrate` dependency. Resilience folds into the axis batteries (broker-disruption → a streaming binding, store-disruption → a persistence binding); load stays in the benchmarks. Layout: the scenario classes and dumb references live in `Edict.Tests.Conformance`; `Edict.Azure.Tests` is demolished, its bindings split into `Edict.Azure.Streaming.Tests` + `Edict.Azure.Persistence.Tests` (mirroring ADR-0042); `Edict.Kafka.Tests` and `Edict.Postgres.Tests` bind the remaining axis providers.

[ADR-0068](0068-deterministic-conformance-scenarios-assert-waiters-poll.md) is the corollary that settles *how a scenario in these batteries is allowed to wait*: scenarios assert order-independent outcomes and the `*Waiters` layer polls, with `Task.Delay` banned in any `*Scenarios.cs` by a no-allowlist guard. It records the four-class wall-clock taxonomy, the deactivate-and-confirm and virtual-clock seams, the sentinel-after pattern, and the boundary with the ADR-0066 chaos contract (which lives in `Edict.Testing`, never in these batteries).

_Revised 2026-06-04 (PRD #297):_ the Postgres persistence binding was consolidated from a separate `Edict.Postgres.Persistence.Tests` back into a single `Edict.Postgres.Tests`. Azure splits its test projects into `.Streaming` + `.Persistence` because it ships **two independent dual-axis packages** (ADR-0042) — there genuinely are two assemblies to mirror. Postgres and Kafka are each **single-axis** providers, so there is no second axis to split on; like `Edict.Kafka.Tests`, the consolidated `Edict.Postgres.Tests` holds both the provider-bespoke seam tests (custom grain storage, fault classifier, storage-exception mapping, bare claim-check store) and the axis-conformance bindings in one assembly.

Enforcement is two drift guards in `Edict.Architecture.Tests`: a **binding-completeness** pure matcher (battery scenarios, provider bindings) → gaps, reflection-wrapped to assert every axis-provider binding project binds **every** scenario in its battery — **no opt-out list**, full within-battery symmetry is the invariant — and the carried-over `EdictTestsConformance_ShouldNotDependOnAnyProviderSdkPackages`, which keeps the batteries and their dumb references free of any provider SDK (`Azure.*`, `Confluent.Kafka`, `Npgsql`), so a reference can never quietly become a real backend.

This supersedes ADR-0027: the M×N cross matrix grew two real backends per test, carried redundant single-axis coverage, and let binding drift go silent (e.g. a `StateWriteFault` left unbound on Kafka despite a stream-sensitive redelivery half). The axis split runs **one** real backend per test, removes the bucket-1 redundancy, and makes drift a red build.

## Considered Options

- **Keep the per-pairing cross matrix (status quo, ADR-0027)** — rejected: M×N growth as providers are added, two real backends provisioned per test (slower, more flake surface), redundant coverage of single-axis scenarios across every pairing, and no structural guard against binding drift — a scenario silently unbound on one provider stays green.
- **Split by axis with reference fidelity for the faked axis (chosen)** — each battery asserts only its own axis against a real backend; the other axis is a dumb reference that honours the contract but is unassertable through the fixture surface. One real backend per test, symmetric coverage enforced by a drift guard, and the decoupling mirrors the Outbox's own.
- **Pure unit tests with mocked/in-memory substrates on both axes** — rejected: the whole point of the conformance battery is real-backend realism. A mock stream cannot reproduce a real broker's redelivery-after-throw, and an in-memory store cannot reproduce the Azure-SDK 404-to-typed-exception translation; both are exactly the green-and-wrong gaps the battery exists to catch.
- **Single reference substrate (one provider, conformance asserts the contract once)** — rejected: a second provider is the entire reason conformance exists — to catch provider-specific drift and prove substrate-neutrality. One provider proves only that the provider works, not that the contract is substrate-neutral, and gives drift nowhere to show up.
