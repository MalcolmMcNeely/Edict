# Projection reads through the grain

Status: Accepted

Projection reads move off the store-direct path and onto the Projection Builder grain, behind a hand-written consumer seam `IEdictProjectionReader<TRow>` (in `Edict.Contracts`, signature-identical to the deleted repository: a token-optional point-get and partition-query). The facade addresses the owning grain through the hand-written `IEdictProjectionBuilder` interface plus a class-name prefix and casts the row back from `object`; the grain serves the read against its own backing store. This mirrors `IEdictSender` on the command side and the Saga progress probe: a generator-emitted typed grain interface would get no Orleans client proxy because Orleans codegen runs before Edict's generator, so the call path has to go through a hand-written interface.

Before this change, consumers read via `IEdictTableRepository<T>` straight against the backing store, on a tier that is a different process from the silo. That shape cannot host a read-your-writes wait (the grain that owns the rows is never on the read path), does not generalise to a future grain-state projection species, and leaks the storage axis into the consumer's read API. The grain-routed read fixes all three: the consumer's read API carries no storage detail (switching a projection's backing store never changes how it is read), the activation that owns the rows is now on the read path so a later wait can be parked there, and the same seam serves every projection species.

The grain read methods (`EdictReadRowAsync`, `EdictReadPartitionAsync`) live on `IEdictProjectionBuilder` and carry `[AlwaysInterleave]`. The attribute is mandatory, not cosmetic, and it is on the **hand-written interface** because Orleans honours `[AlwaysInterleave]` only on the grain-interface method the client proxy dispatches through — an attribute stamped on a generated grain class or a generated derived interface would be ignored for interleaving and manifest, once a blocking wait lands in the next slice, as an intermittent hang. A Projection Builder grain is single-activation and turn-based, so a parked read that ran as a normal turn would hold the activation's only thread while the stream-delivery turn that would satisfy it queues behind, self-deadlocking. The interleave is on the framework interface every projection inherits, and a reflection test in `Edict.Core.Tests` pins it so it cannot silently disappear.

The seam's `partitionKey` is the projection's **routing key**: for a per-aggregate projection this is the aggregate's `[EdictRouteKey]` Guid, which is also its store partition, so a caller passes the aggregate Guid exactly as before; the grain maps to its own `DefaultPartitionKey` internally, so a singleton projection (the dead-letter projection) is addressed by its singleton key while reading its own fixed partition. The facade resolves the row type to the owning projection grain class through a generator-emitted route map (`EdictProjectionReadRegistrar` + `[assembly: EdictProjectionReadRoutes]`, collected at `AddEdict()`, exactly the command-route registrar pattern); the framework's own dead-letter projection route is hand-registered in `AddEdict()` because Edict's generator does not run on `Edict.Core`.

`IEdictTableRepository<T>` is **deleted** with no escape hatch. If query-heavy table reads become a problem later, that is solved then; keeping the store-direct path now is extra surface that would have to grow its own read-your-writes story. The internal store seams remain: `IEdictTableWriteStore<T>` (which gains `QueryPartitionAsync` alongside its existing point-get) and `IEdictTableStoreFactory`, because the grain uses them to write and to read on the consumer's behalf, and the throughput harness and persistence-conformance fixtures read through them store-direct (off-grain — the right shape for a latency measurement and for verifying a write landed independently of the grain read path). The provider write-store classes (`AzureTableWriteStore<T>`, `PostgresTableWriteStore<T>`) become public so the harness can construct them, replacing the deleted public repositories.

Deleting the generic repository removes the backing of the operator forensic facade `IEdictDeadLetterRepository`. That facade is **kept** — forensics is a distinct operator surface — and re-backed on the grain read against the dead-letter projection's singleton key. The dead-letter projection is itself a singleton List Projection Builder, so it rides the same read mechanism; the implementation renames from `TableBackedDeadLetterRepository` to `GrainBackedDeadLetterRepository`, and its grain-key filter logic is unit-tested in `Edict.Core.Tests`.

The abstract `EdictProjectionBuilder` root stays the discovery marker (for the generator and analyzer EDICT009) and now also declares the read surface, with a default that throws `EdictUnsupportedProjectionReadException`: a projection that keeps no readable row store (one that exposes its state through a bespoke grain interface) has nothing for the read facade to return, and the facade only ever routes row types owned by a List projection, so the throw is a direct-call programming-error net, never reached through `IEdictProjectionReader`. `EdictListProjectionBuilder<TRow>` overrides it with the real store-backed read. The future grain-state species slots in as a concrete sibling under the same root and inherits the identical read mechanism.

This supersedes ADR-0011, ADR-0013, and ADR-0032, which described the store-direct read tier, the read-only `IEdictTableRepository` seam, and the in-grain row cache keyed to that read model. Those remain as point-in-time records and are not rewritten. The in-grain single-writer row cache (ADR-0032) is unaffected as a write-path optimisation; only its framing as the backing for a store-direct read is superseded.
